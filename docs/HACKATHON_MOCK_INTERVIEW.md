# 黑客松答辩 · 模拟问答（含参考答案）

产品：**情报驱动 面试备战**  
线上：https://8.219.189.79.sslip.io/  
演示：`/interview?demo=1`（不写历史）  
仓库：https://github.com/GoBang5/diqi

用法：先把「30 秒开场」练到不看稿。后面按场次练，**先自己答 60–90 秒，再对照参考答案**。括号里的「再追」是评委下一刀，不要主动往那说，等被问再答。

不要说的三句话：

- 「我们不会画出假图」——情报 ≥3 条目前不校验是否对得上这场。
- 「两轮绝对不误伤会讲的人」——会，承认并给出改法。
- 「和 ChatGPT 的区别是模型更好」——评委要的是流程差异，不是 DeepSeek。

---

## 0. 30 秒开场（必背）

备考焦虑不是没题刷，是三个不知道：这场考什么、自己站不站得住、下一步练哪三条。

ChatGPT 能扮演面试官，但不会先聚合**这一场**的情报，也不会在答不出新事实时停下来。我们做的是：先锁定去向和选拔要求，收集面经，聚成考情画像，再按四类题源追问；判定的不是答得好不好，而是有没有新增可验证事实。复盘只给下一步三刀。

演示走字节电商交易组那条预置材料，打开即用，不用登录。

## 1. 产品判断（评委第一轮）

### Q1. 一句话，这是什么？给谁用？

**参考答案**  
给准备下一场实习或夏令营面试的本科生。一场备战只锁定一个去向 + 一个方向。先摸清这场怎么考，对照简历练；练完告诉你站住了哪些、还差哪三刀。不是通用刷题站，也不是情绪安慰。

**再追**  
为什么不做全岗位、不做成「终身备考档案」？  
→ 情报必须聚得起来。去向一散，面经对不上，画像就是假的。学生也是一场接一场，产品按场组织，不按人设长期档案。

---

### Q2. 和「打开 ChatGPT 当面试官」差在哪？评委为什么不该觉得你只是套了层界面？

**参考答案**  
ChatGPT 默认不知道**这场**考什么。它没有这场的面经、选拔要求和简历对照，出题容易变成通用八股；答完也不会收口成「只补这 3 个」。

我们多的是一条链，不是更好的模型：

1. 情报先定范围；条数太少又对不上这场，不硬画画像。  
2. 出题按四类题源：面经考点、经历已覆盖、经历待核实、要求未覆盖。  
3. 追问不打分，只判有没有新增可验证事实（机制、参数、量级、场景、取舍、本人动作）。  
4. 复盘只给下一步三刀，进度来自本场实测。

刻意没做登录、语音视频、爬小红书/知乎——评委打开就能走完主路径。

**再追**  
那为什么还要用 DeepSeek？  
→ 出题、追问、面经甄别需要语言模型。判定类调用低温（分析/归并甚至 temperature 0）。但摘录能不能用，不信模型，用代码在原文里核验。模型是零件，产品判断是那条链。

---

### Q3. 最初方案是什么？为什么改？

**参考答案**  
最初做「面经打假 + 考纲自评地图」：学生对着考点自己打钩。后来发现学生更急的是**下一场怎么答**，不是给面经打分。主路径改成：简历 × 选拔要求 × 情报的深挖训练。考纲收成考情画像，不再让用户逐点自评。

打假没扔掉：商业意图和题目能不能用仍拆开；广告帖里的真题仍可进考情，只是权重低。

**再追**  
有没有证据证明学生更急「下一场」？  
→ 黑客松里没有大规模用户实验，这是我们自己当用户时的判断，加上评委必须 3 分钟走通主路径。自评地图点击多、反馈弱；改成练完给三刀，演示闭环更短。没有 A/B 数据，不要说「验证了提升 xx%」。

---

### Q4. 竞品呢？牛客刷题、ChatGPT、通用模拟面试产品。

**参考答案**  
- 牛客：题库和面经在，但不按「你这场 + 你这份简历」收口，容易变成看完仍不知道自己差哪三条。  
- ChatGPT：扮演面试官成本为零，但范围是模型猜的，停不下来，容易刷出虚假自信。  
- 通用模拟面：多为固定题或岗位大类，缺少这场情报，也缺少「答不出新事实就停」。

我们赌的是：**情报是一等公民**。没有情报就只对照简历和选拔要求出题，不假装有内部消息。

**再追**  
没有情报时产品还有价值吗？  
→ 有。四类题源里，经历已覆盖 / 待核实 / 要求未覆盖不依赖面经。缺的是「这个组真实怎么问」。产品会降级，不装。

## 2. 主流程与演示口径

### Q5. 现场演示你怎么带？评委只给你 3 分钟。

**参考答案**  
不要从空白表单填起。走演示模式：首页「演示模式」或 `/interview?demo=1`。

口播顺序：

1. 这场已经锁死：字节电商交易组，简历和选拔要求已在。  
2. 情报列表：几条面经、可信度。点开画像：高频考点 + 简历匹配缺口。  
3. 针对训练：选「情报针对训练」、难度「加压」、少题快跑。答两轮：一轮给机制，一轮给数字怎么测或失败怎么办。  
4. 复盘：站住 / 被追回来 / 下一步三刀。强调演示不写历史。

**再追**  
为什么演示不写历史？  
→ 评委和观众会反复打开同一条链接。写进本机历史会污染「真实备战」和演示数据。演示材料是虚构的，入库会造成假进度。

---

### Q6. 五步各自产出是什么？哪一步可以跳？

**参考答案**

| 步骤 | 用户做什么 | 系统产出 |
|---|---|---|
| 这场面试 | 去向、方向、简历、选拔要求 | 锁定本场材料 |
| 面试情报 | 检索 / 贴链接 / 粘贴 / 上传 | 带可信度的情报列表 |
| 考情画像 | 看 | 高频考点、要求×简历匹配 |
| 针对训练 | 时长、题量、难度、完整模拟或情报针对 | 四类题源追问 |
| 复盘 | 回看 | 已验证 / 经不起 / 未覆盖，下一步三刀 |

情报可以空着进训练，但画像在「太少且对不上」时不画。训练可以选完整模拟（四类都问）或只练情报里反复出现的点。

## 3. 情报与合规（高频深挖）

### Q7. 情报从哪来？为什么不爬小红书和知乎？

**参考答案**  
公开收集：按去向、方向检索公开网页，或用户贴链接抓全文。手动加入：粘贴师兄整理稿、上传 PDF/DOCX/TXT/MD——很多真情报不在搜索引擎里。

运行时不登录小红书、知乎，不绕过验证码，这两站不纳入自动检索。评委环境、合规、风控都过不去；产品也不是爬虫竞赛。用户把公开整理稿粘进来，我们认这条路径。

**再追**  
那公开检索质量会不会很差？  
→ 会。所以检索只是入口，不是唯一入口。手动粘贴是一等能力。检索还要过滤招聘广告、课程推广这类噪声。质量差时，用「对不上不画图」兜底，而不是用差情报硬画。

---

### Q8. `verdict` 和 `contentTrust` 为什么拆成两个？广告帖还进不进考情？

**参考答案**  
这是产品核心判断：**商业意图和题目能不能用是两件事。**

- `verdict`：这篇帖子想干什么。trustworthy / suspicious / promotional。  
- `contentTrust`：里面的题能不能用。usable / partial / unusable。

机构引流也需要真题获客，所以广告帖里的题仍可能真实；看起来真诚的帖也可能拼凑。两个分数合成一个，会把「能用的真题」和「这篇是广告」绑死。

进考情时 promotional **不归零**，权重 0.15（真面经 1.0，可疑 0.4），再乘时效衰减。避免一批广告靠条数把假考点顶上去，也不因是广告就把真题扔掉。

**再追**  
权重 0.15 怎么来的？  
→ 工程上的量级选择：显著低于真面经，多条广告叠加上去仍弱于一篇近期真面经。没有大规模标注集调参。答辩说「量级设计」，不要说「数据拟合出来的最优值」。

---

### Q9. 怎么防模型编证据？「看起来很真的摘录」怎么办？

**参考答案**  
prompt 要求指控必须逐字摘自原文；这不够。代码里还有强制校验：非中立信号的 quotes 必须能在原文里找到（归一化空白和标点后 substring），短于 4 字的摘录丢掉。不利于可信度但找不到原文的信号，降级为中立——**宁可少判，不编证据**。

举证责任在指控方：说这篇有问题必须拿出原文；说没问题往往是「某样东西不存在」，无法引用，不强行让模型编一句「全文没有微信」。

**再追**  
归一化会不会把不同句子判成同一句？  
→ 只去掉空白和常见标点，不改写措辞。改写过的摘录对不上原文，会被丢。这是防幻觉，不是语义匹配。同义改写过不了，这是故意的。

---

### Q10. 情报少、对不上，为什么不画画像？阈值怎么定的？

**参考答案**  
少于 3 条算稀缺。0 条不进画像。1–2 条必须对上这场，规则是字面匹配，不再调一次模型：

- 正文或标题出现去向名称，或  
- 方向词至少命中 2 个，或  
- 选拔要求分词至少命中 5 个。

≥3 条目前**不再做这场匹配**，直接进画像。稀缺时用关键词挡无关材料；条数够了就放行，是用数量换「学生只有两三条师兄微信也能用」。

**再追（压力）**  
我贴 2 条无关面经，标题写上公司名，会不会过？  
→ **会。** `companyHit` 是子串包含。这是真洞。稀缺匹配的假阳性是「无关材料混进来」，不是假阴性。下一刀应改成：去向和方向同时命中；≥3 条也抽检相关度，不能只数条数。

**再追**  
≥3 条全是别的组的面经呢？  
→ 当前会画。这是更大的洞，答辩必须主动认，不要等评委演示打穿。

## 4. 出题、追问、难度（最容易被压穿）

### Q11. 四类题源分别干什么？为什么要用户看到这四个词？

**参考答案**

| 书面标签 | 内部类型 | 作用 |
|---|---|---|
| 面经考点 | `intel_hit` | 这场出现过，不是通用题库；简历没写也要问 |
| 经历已覆盖 | `resume_match` | 要求和简历重合，深挖你到底做了什么 |
| 经历待核实 | `resume_risk` | 数字或职责偏满，要可核验依据 |
| 要求未覆盖 | `jd_gap` | 要求有、简历没有；允许说不会，问清边界 |

用户看到的是书面四词，不是内部枚举。早期用内部词，学生看不懂「为什么问这个」。现在每题能对上「这场为什么这样问」。

无情报时不做 `intel_hit`，只用后三类。

---

### Q12. 追问最多两轮。判定标准是什么？两轮是不是拍脑袋？

**参考答案**  
判定不是「答得好不好」，是这一轮有没有**新增可验证事实**。复述、套话、「大概/应该是」、说不清，记为无增量，当场 `collapsed`（经不起追问）。连续两轮都有增量，才 `verified`。

两轮写在 `MAX_PROBE_TURNS`。试过三轮：连「真做过」的回答第三轮也会开始复述，整张图全红。产品要反对没有实测的满分，全红会加重焦虑。八股往往第一轮就露馅。

追问必须咬上轮最弱的一环，禁止「再详细说说」。

**再追（压力）**  
第一轮把机制讲完，第二轮只能复述，会不会被判经不起？  
→ **会。这是误伤。** 规则是每轮都必须有增量。我们靠第二问改去问边界、失效、数字口径来降低误伤。若第二问生成质量差、还在问同一层，讲得清楚的人会被罚。产品选择是：**宁可不给绿，也不给假绿。** 复盘里仍能看到第一轮已经给出过事实。若再改：第一轮已经覆盖机制+边界+量级，允许提前 verified。这周没做，是怕背稿答得很满的人混过去。

---

### Q13. 舒适 / 常规 / 加压，真的不是同一组题换个标签吗？

**参考答案**  
早期确实几乎一样，因为只把难度写在 UI 上，prompt 不够硬。后来出题和追问都带 `difficultyHint`，三档换角度：

- 舒适：只问做过的部分和成功路径，标题像「XX 是怎么做的」。  
- 常规：机制问清后再追一层边界，但不用失败路径当主轴。  
- 加压：至少一半标题落到失败路径、数字口径或权衡；开场就对质，禁止写成「如何保证」。

同一考点，加压不该再问实现细节。

**再追**  
怎么证明三档真的不同？  
→ 可以现场切同一份演示材料，舒适开「怎么做的」，加压开「这个数字怎么测的 / 失败怎么办」。没有离线自动评测说「题目差异度 xx」。评委可以 30 秒内看出来。

---

### Q14. 「新增可验证事实」会不会太严？短回答怎么办？

**参考答案**  
短不等于没增量。一句准确的机制胜过一段套话。反过来，长篇但全是「我们做了优化、效果很好」，没有机制、参数、量级，就是没增量。

这和产品要反的焦虑是同一件事：虚假的「答得很完整」比「我不会」更害人。

---

## 5. 画像、匹配、复盘

### Q15. 简历匹配分是模型打的吗？

**参考答案**  
不是。`scoreResumeFit` 不调模型：看简历原文里有没有出现已聚合考点标题/问法，以及选拔要求里切出的短词。分数夹在大约 18–92，避免 0 和 100 造成虚假精确。

这是词面重合，不是语义理解。「做了限流」和 JD 写「熔断」对不上，会进缺口。这是刻意的：面试里被追的往往是**没写到的词**，不是同义句。

**再追**  
会不会漏掉同义表述？  
→ 会。我们接受漏检，避免模型把没写的经历判成「已覆盖」。匹配只提示缺口，真正深挖仍靠训练题的 `resume_risk` / `jd_gap`。

---

### Q16. 复盘为什么不看平均分？下一步为什么只给 3 个？

**参考答案**  
平均分会把「3 个站住、2 个被追回来」抹成 70 分，学生不知道下一刀砍哪。我们看三类：已验证、经不起追问、尚未覆盖。下一步只给三条，是为了对抗「清单太长等于没清单」。

进度条必须来自本场真实问答。没有实测支撑的满分会加重焦虑——这是写在 PRD 里的核心判断。

**再追**  
3 是不是拍的？  
→ 是容量选择，不是实验最优。再多学生做不完。不要说成科学结论。

---

## 6. 工程与部署

### Q17. 技术栈？数据存在哪？为什么不用登录、不用数据库？

**参考答案**  
Next.js App Router + TypeScript + Tailwind。出题和判定走 DeepSeek。练习和复盘在浏览器 localStorage，不上传服务器。

评委打开即用，这是黑客松约束。上账号体系要注册、忘记密码、隐私政策，主路径会被打断。本机存储的代价是换浏览器、清站点数据会丢历史——产品按「一场备战」设计，可接受。

**再追**  
换电脑怎么办？  
→ 当前不能同步。诚实说这是刻意不做。简历建议可以写回本场材料再练一轮，但仍在这台浏览器里。

---

### Q18. 部署在哪？为什么必须香港或新加坡？

**参考答案**  
轻量云主机 + Caddy 自动 HTTPS。国内地域走 80/443 要 ICP 备案，本项目对 HTTPS 有硬依赖（浏览器安全上下文、评委链接）。所以机器在香港或新加坡。

服务：`systemctl status ai-interviewer`  
目录：`/opt/ai-interviewer`  
域名：`https://8.219.189.79.sslip.io/`

**再追**  
sslip.io 是什么？挂了怎么办？  
→ 用 IP 拼出来的免费证书域名，方便评委点开。不稳定性是已知风险：证书续期依赖 Caddy 和该服务。正式产品应备案或用自有域名。黑客松里用它是为了省掉域名购买和审核时间。

---

### Q19. AI 写的代码，你负责什么？

**参考答案**  
代码在 Cursor 里辅助生成。人定的是：主路径、刻意不做、判定标准（增量而不是分数）、情报与可信度拆分、不硬画画像、三档难度必须换角度。验收标准也是人定的：演示能 3 分钟走通、摘录必须在原文里、评委无需登录。

不要假装手写了每一行。评委看 commit 也能看出来。加分项是产品判断和取舍，不是「我没用 AI」。

---

### Q20. 摘录核验、情报匹配、追问判定，哪些在模型里、哪些在代码里？

**参考答案**  
- **模型**：面经五维分析、考点归并、出题、追问生成、是否有新事实的初判。  
- **代码硬约束**：摘录必须出现在原文；情报稀缺时的字面匹配；广告权重和时效衰减；两轮上限；难度 hint 注入 prompt；判定类低温。

评委听到「AI 应用」时，要主动把这条边界讲清：能幻觉的部分不单独信任，能规则化的不交给模型。

## 7. 压力连环（一口气练）

下面按评委打断风格写。左边是问，右边是该马上接的一句；展开用上面各题的参考答案。

**P1.** 你不就是套了个 ChatGPT 吗？  
→ 套界面不会「对不上不画图」，也不会「没新事实就停」。区别在范围和停机条件。

**P2.** 情报是搜索拼的，假的怎么办？  
→ 五维甄别 + 摘录代码核验；广告降权不删除真题；对不上不进画像。仍可能假阳性，≥3 条是已知洞。

**P3.** 学生把假经历练成「经得起追问」怎么办？  
→ 我们验的是「能说出可验证细节」，不是去用人单位背调。产品目的是让泡沫在训练里破，不是发证书。`resume_risk` 就是冲着写满的数字去的。

**P4.** 模型把「大概用了 Redis」判成有增量怎么办？  
→ 有。低温和 prompt 约束「大概/应该是」算无增量，但不能保证。这是 LLM 判定的上限。我们没做双人标注一致性。答辩说「规则方向对，执行有噪声」。

**P5.** 为什么信任 DeepSeek 而不是本地小模型？  
→ 黑客松时间和机器约束。判定要中文、要 JSON、要跟着简历原文咬。API 能在一周内闭环。代价是数据和隐私走模型厂商——所以简历和问答默认不在我们服务器落库，但调用时仍会进模型上下文。这点必须主动说。

**P6.** 如果我清掉 localStorage，用户数据呢？  
→ 没了。没有云端账号。这是评委打开即用换来的。

**P7.** 夏令营和公司实习考法完全不同，一套流程怎么通？  
→ 选拔要求允许贴招生简章；情报手动粘贴本来就是为微信里的学长消息。权重上还没按「夏令营 / 实验室 / 公司组」拆开，这是「若再有一周」里的项。现在靠用户锁定去向和方向，不靠系统自动分类。

**P8.** 你最失败的一次产品判断是什么？  
→ 难度三档最初只改了文案，出题几乎一样，等于功能假实现。后来强制 hint 进出题和追问。另一件：简历输入框用了不稳定的 `key`，导致打不了字——演示级事故，修的是工程细节不是愿景。

**P9.** 若再给你一周，为什么是那三件事而不是补登录？  
→ 登录不增加「下一场答什么」的信息。一周该补的是：同一考点隔几天再练看是站住还是又塌；情报按去向类型加权；从面经生成有信息量的反问。登录是正式产品的事，不是黑客松主路径。

**P10.** 这能商业化吗？  
→ 黑客松目标不是商业化。若要讲：可能是按「场」收费的备考工具，难在情报供给和版权。更诚实的说法：现在验证的是「情报 × 简历深挖」这条交互是否比裸聊模型更可演示。没有付费用户，不要讲 ARR。

## 8. 现场演示时的口播稿（可对着点）

1. 「这不是随机刷题。先定这场去向。」  
2. 「情报可以搜，也可以把师兄微信粘进来。少且对不上，我们宁可不画图。」  
3. 「画像是高频考点加简历缺口，匹配是词面核对，不是模型打分。」  
4. 「训练有四类来源。加压档会直接问失败和数字怎么测。」  
5. 「两轮追问，看的是有没有新事实。复述就停。」  
6. 「复盘不给平均分，只给站住了哪些、下一刀三条。」  
7. 「演示模式不写历史。数据在你浏览器里，我们服务器不存问答。」

## 9. 评委可能打穿的实验（自己先做一遍）

| 操作 | 你应该观察到 | 若没发生，答辩怎么说 |
|---|---|---|
| 演示模式走完训练 | 不写入 `/history` | 这是硬需求，坏了就是 P0 |
| 情报 0 条进画像 | 被拦住 | 符合设计 |
| 2 条无关面经 + 标题带公司名 | **可能放行** | 承认假阳性，讲改法 |
| 舒适 vs 加压同一材料 | 标题和首问角度不同 | 若仍相同，说这是修过的 bug，现场以当前线上为准 |
| 第一轮只说「用了 Redis 做缓存」 | 继续追或判无增量 | 无机制、无参数，按设计应不稳 |
| 粘贴带「加微信领资料」的帖 | verdict 偏 promotional，题仍可能 usable | 拆分两个字段的现场证据 |

## 10. 数字与证据边界（写进简历前也用这张表）

| 可以说 | 不能说 |
|---|---|
| 追问上限 2 轮，三轮回测会全红 | 「准确率 xx%」「误伤率 xx%」 |
| 广告权重 0.15，90 天内时效 1.0 | 「权重是训练出来的」 |
| 简历匹配是词面重合，分数夹紧 | 「语义匹配准确」 |
| 线上可打开、演示可走通 | 「已有 xx 日活」 |
| 评委无需登录 | 「生产级账号与隐私方案」 |
| AI 辅助写代码，产品判断由人定 | 「独立实现全部算法」 |

## 11. 1 分钟收口（终面/结束被问「还有什么要补充」）

如果只留一句：我们把面试备考从「找个 AI 陪练」改成「先核对这场事实，再决定练什么，练完只许带走三刀」。模型会幻觉，所以摘录、稀缺匹配、权重放在代码里；模型负责出题和往下追。没做的（登录、语音、爬墙内社区、≥3 条情报的相关度）都是为了评委当场能走通，不是不知道那些更完整。
